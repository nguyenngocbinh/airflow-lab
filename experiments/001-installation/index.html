Install Apache Airflow 3.3.2 on Windows

Objective: get a local Airflow stack running with Docker Desktop + WSL2, while documenting the real troubleshooting path.

01 · Environment

  • Windows + WSL2
  • Docker 29.8.1
  • Docker Compose 5.5.1
  • Apache Airflow 3.3.2
  • PostgreSQL 16
  • Redis 7.2-bookworm
  • Workspace: D:\airflow

02 · Initial setup

mkdir D:\airflow
cd D:\airflow

mkdir dags
mkdir logs
mkdir plugins

The official Airflow Docker Compose file was placed at D:\airflow\docker-compose.yaml. The .env file used AIRFLOW_UID=50000 and a generated Fernet key.

03 · Disk issue

During the first Docker startup, Docker reported an I/O error while writing containerd metadata. The host had only about 4.5 GB free on C: while D: had more than 300 GB free.

commit failed:
write /var/lib/desktop-containerd/.../metadata.db:
input/output error
Lesson: check Docker storage early. For this lab, Docker Desktop's disk image was moved to the larger D: drive rather than manually copying the underlying VHDX.

04 · API Server failed to start

After docker compose up -d, PostgreSQL and Redis were healthy, but the API server repeatedly restarted with exit code 0.

docker compose ps -a
airflow-airflow-apiserver-1   Restarting (0)
airflow-postgres-1             Up (healthy)
airflow-redis-1                Up (healthy)

05 · Isolate the image

The key debugging step was to stop blaming Compose and test the Airflow image directly.

docker run --rm apache/airflow:3.3.2 airflow version

The first local image produced no output. Bypassing the entrypoint exposed the underlying problem:

docker run --rm --entrypoint /bin/bash apache/airflow:3.3.2 -c "echo HELLO; python --version; which airflow; airflow version"

HELLO
Python 3.13.15
/home/airflow/.local/bin/airflow

ModuleNotFoundError: No module named 'airflow'

That meant the local Airflow image was incomplete or corrupted: the executable existed, but the Python package could not be imported.

06 · Recovery

docker compose down
docker ps -a --filter "ancestor=apache/airflow:3.3.2"
docker rm -f <remaining-airflow-container-ids>
docker rmi apache/airflow:3.3.2
docker pull apache/airflow:3.3.2

Before restarting Compose, the refreshed image was tested independently:

docker run --rm apache/airflow:3.3.2 airflow version

3.3.2

07 · Final result

docker compose up -d
docker compose ps
✔ airflow-apiserver        Up (healthy)
✔ airflow-dag-processor    Up (healthy)
✔ airflow-scheduler        Up (healthy)
✔ airflow-triggerer        Up (healthy)
✔ airflow-worker           Up (healthy)
✔ postgres                 Up (healthy)
✔ redis                    Up (healthy)

08 · Access

http://localhost:8080

09 · What I learned

  • Debug from infrastructure → image → container → entrypoint → command → application.
  • A container exiting with code 0 can still be unusable.
  • Test a base image independently before changing a large Compose configuration.
  • Keep Docker data on a disk with enough capacity.
  • Do not use docker compose down -v while trying to preserve database volumes.
